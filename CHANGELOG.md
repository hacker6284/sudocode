# Changelog

## v0.7.3

- **Uniform copy-on-write on py/js.** `dup` of a list (including `text`), map, set, or record is unconditionally an O(1) share. No alias-safety scan, no per-type special case, no memoized flag to invalidate. A write forks that object if it has a second referent. Nested mutation (`xs[0].append`, `q.items.append`) goes through `at_mut` / `field_mut` / `map_at_mut`. Tuples stay immutable (slot stores already share). 0.7.1's COW only shared lists of scalars/tuples — exactly one consumer's sort row. `List<text>` and `List<record>` still scaled with payload; they do not now.
- **Read-only destructure skips `dup`.** If no binding from a tuple unpack is assigned, index/field-mutated, passed as `inout`, or used as a mutating-builtin receiver, py/js unpack the source directly. `a, s = ys[0]; s.append(...)` still copies — this is a `never_written` refinement, not a removal of the rule. Composite `sort_by` comparators stop paying two tuple dups per comparison.
- **Dup counters are gated.** `_count_list_dup` / leaf stats run only after `reset_dup_stats()`. Programs that are not measuring do not pay (~10% on `sort_by` in 0.7.1). Same principle as backend-guide §4.20.
- Copy-volume gate `//stdlib:sorting_sort_copy_complexity` now also asserts `copy_texts`, `sort_texts` (`List<text>`), and `sort_wides` (`List<record>`) are independent of unread payload width. Criterion 5 is restated as work-per-dup, not "leaves ≤ 4× the list".
- `bench/sortbench.sudo` gains `sort_rows_bykey_checksum` and E7 (`sort_texts` / `sort_records`). No API, protocol, or language change. Host-facing records stay the generated dataclass (`out_record` walks the tree), not the COW handle. An inout of a record field (`mutate(q.items)`) goes through `field_mut` so a shared parent forks.
- 0.7.2 was not released. It would have memoized the 0.7.1 alias scan (the correctness-sensitive half of a one-release fix). Uniform COW deletes that scan instead.

## v0.7.1

- **py/js lists are copy-on-write.** `_rt.dup` of a list of alias-safe elements (scalars, tuples — nothing that can be mutated in place through a shared identity) is O(1): a new wrapper shares the backing array; the first write with a second referent forks. Nested lists, maps, sets, and records still get a new array of `dup`'d elements, so `xs[0].append` cannot leak to another referent. Tuples themselves are unchanged. No language, API, or protocol change. Host-facing list/text values are still plain Python lists / JS arrays on the way out.
- **A swap of distinct locals is a rebinding.** Var-var parallel assign (`a, b = b, a`) stays a `TupleAssign` instead of being lowered to four temporaries. py/js emit it without `dup`. `gcd`'s `a, b = b, a mod b` now reads as that in the generated source. Combined with COW, `sort_by` on `List<(int, text, text, int)>` is the fastest option (n=4000: 0.26s vs 0.48s for three `sort_by_key` passes). Zig's `TupleAssign` now writes inout targets through the pointer into `ret_alloc` (it previously only saw `x, y = f()`).
- **Tuple slot stores share.** `buf[k] = items[a]` for a tuple element does not `dup` — tuples have no in-place mutation path. Unpacking still copies, so `a, s = ys[0]; s.append(...)` cannot leak. Records and nested lists still copy.
- **Corrected diagnosis.** 0.6's notes and `sort_by`'s doc comment blamed the comparator call for composite-element cost. The generated code does not copy there (`never_written` elides it). The cost was the four whole-list copies per merge pass plus a deep copy per `buf[k] = items[a]`. The comments and `stdlib/README.md` now say so.
- New op-count gate `//stdlib:sorting_sort_copy_complexity`: when n doubles, whole-list copies stay flat and leaf copies stay n log n; unread text width must not scale leaves. Absolute counts are a snapshot of this runtime (edit them if a later impl copies a different constant). `bench/sortbench.sudo` is the isolation harness from the 0.7.1 requirement.
- Side effect, as written at ship: `dup(text)` is O(1) too, so the 0.7.2 "text is List<int>, copying one is O(length)" item dissolves on py/js. **The consumer measured otherwise** — the copy is O(1), the alias-safety *scan* on the same path is not (`copy_texts` 229× across widths). Corrected in 0.7.3 (the scan is gone; `text` is a COW handle).

## v0.7.0

- **BREAKING — emit protocol 3 → 4.** The JSON shape is unchanged; the interpretation is not. A nominal type is now a program-unique IR symbol, and types that cross a module boundary live in a synthetic leaf module named `sudo_types` (first in `modules`). `sudoc` and external emitters must be upgraded together. A protocol-3 backend fed a v0.7 program emits code that compiles and is silently wrong for py/js constructors (unqualified `NewRecord` / variant refs). **Fix for an external backend:** accept `"protocol": 4`; emit a module literally named `sudo_types` like any other; treat `imports` as unit dependencies; resolve a nominal type's home unit via the program-wide decl table rather than assuming `Ty::Record(n)` is declared in the module being emitted.
- **A caller-declared `record` or `enum` may be used as a type argument to an imported generic.** `sorting.sort_by(xs, less)` with `xs: List<Thing>` is legal. Instantiations still land in the defining module; the template body never names the foreign type. Concrete imported functions whose signatures mention a module-local record/enum are still rejected, as is `dep.Thing` in type position.
- **Nominal types have program-global identity.** Two modules may declare the same name; they are distinct. The compiler assigns a unique IR symbol (the bare name when unique program-wide, otherwise `Sudo_M…` on *every* colliding decl). Types that actually cross a module boundary move into `sudo_types`; a program with nothing escaping emits no `sudo_types.*` file and is otherwise unchanged.
- **Silent diagnostic-text change:** when two modules declare the same nominal name and at least one escapes, both symbols become `Sudo_M…`. That spelling appears in `canon` output (assertion-failure diagnostics). Behaviour is unchanged; the old `{"r": "Thing"}` was already ambiguous with two live `Thing`s.
- **New `sudo_types.*` file** in the generated set when a type crosses a module boundary. People read this output.
- Programs rejected (or broken) before now compile; no previously-accepted program is rejected. User modules cannot be named `sudo_types`.
- Instantiation runaway guard raised from 32 to 256 distinct instantiations per template, plus a type-argument depth cap of 32 (catches unbounded nesting without firing on many distinct shallow types).
- Rust backend: the crate root (entry) emits `mod` for every module; non-entry files emit none; qualified calls are `crate::dep::f`. Fixes a latent diamond where `#[path] mod` from two importers compiled a module twice.

## v0.6.0

- **BREAKING — emit protocol 2 → 3. `sudoc` and external emitters must be upgraded together; there is no compatibility window.** `IrParam` gains a required boolean `never_written`, and emit requests are stamped `"protocol": 3`. Both sides match the version exactly and reject unknown *and* missing keys, so a protocol-2 emitter fails against v0.6.0 `sudoc` and a protocol-3 emitter fails against v0.5.0. **Fix for an external backend:** accept version 3 and accept the `never_written` field — ignoring it is correct, since it only enables an optimization. **Semantics:** a fact about the *callee body only* (the parameter is never assigned, never index/field-mutated, never a mutating-builtin receiver, never forwarded as `inout`). Always `false` for `inout` params. It says nothing about call-site aliasing or whether the function's address is taken. An emitter that skips only an internal entry-copy may use it alone, but must still re-dup a by-value argument that shares a root local with an `inout` argument in the same call; an emitter that *changes calling convention* on it must additionally combine it with an address-taken analysis.
- **BEHAVIOUR CHANGE — `regex` now enforces a total compile-size budget of 100000 NFA states.** Patterns that previously compiled may now fail loudly with a size error. A per-bound cap alone was never a size guarantee: bounds nest and multiply, so `(a{1000}){1000}` is ~10^6 states and `((a{1000}){1000}){1000}` ~10^9, from a pattern a couple of dozen characters long. The budget is checked incrementally with early abort, so an over-budget pattern is rejected rather than materialized, and `regex_is_valid` inherits it. This is what makes the module's standing claim — that callers may drop their own timeout/complexity gates — true rather than merely written down.
- **Spec §12 evaluation order systematically enumerated and audited for the first time.** 100 conformance cells derived from the IR's `Place` recursion and its multi-subexpression `IrExprKind` constructors (not hand-picked), each ordering case written with its mirror. That audit found and fixed **eleven** violations across six of the seven backends: preconditions raised before a later argument was evaluated (`filled`, `insert`, `swap` on zig/hs); assignment evaluating the RHS before the place's index or key (c/hs/py); constructor arguments left unordered; `NewVariant`/`MutBuiltin`/`Index` evaluating right-to-left (hs); the outer index evaluated before the base index (rs); nested `Index`-of-`Index` assignment failing to compile (swift); `place_ptr` panicking the compiler on a well-typed mutating method over an indexed receiver (zig); and the mutating-method *receiver* path failing to compile (swift) or evaluating arguments before the receiver's key (rs). §12 also now states the assignment-order rule explicitly, which was previously left to inference.
- **Cross-module concrete function references are now values.** Previously every qualified function reference was rejected, so no module could export a comparator or key extractor — in a language with no closures, that removed higher-order use across module boundaries entirely. `sorting.sort_by(words, strings.lex_less)` now works. Generic functions still cannot be referenced as values (spec §5.2), and functions with an `inout` parameter are now rejected as values too, because `Ty::Func` carries no per-parameter modality and such a reference would be a type that lies. That restriction also binds same-module references that previously compiled.
- **New sorting API.** `sort_index_of_keys`, `apply_permutation`, `sort_by_key`, `lower_bound`, `binary_search`. With no closures, `sort_by`'s comparator takes two whole elements, so a sort crosses a call boundary n log n times carrying composites; decorate-sort-undecorate makes it n key extractions plus n log n comparisons on keys. Measured on py, 20k rows of `(int, text, text, int)` sorted by the int: 13.41s → 0.99s. Multi-key sorts use the LSD-radix recipe in `stdlib/README.md`, which is legal because the sort is stable.
- **`sort_by` is a stable merge sort**, not the swap-based insertion sort it had been despite the spec describing it as generalizing an O(n log n) primitive. 40k reverse-sorted ints: 2.47s → 0.22s.
- **Quadratic accumulators fixed** in `strings.join` and `bigint.big_to_text`; both built a `text` with `out = out + piece` in a loop. join at N=4000: 56.29s → 0.033s. `big_to_text`'s base-10^9 conversion was always linear — only its assembly was quadratic.
- **`strings.index_of` no longer calls `match_at` in its loop.** `match_at` takes the haystack by value and only py/js/zig elide that copy, so the search was quadratic in *copying* on rs/c/swift/hs before doing any comparison. rs, 100k haystack: 1.42s → 0.00s. **No CI gate accompanies this** — wall-clock gates are rejected here as flaky, and the op-count harness runs on py where the copy is already elided, so no CI-safe instrument can observe it.
- **12 new `strings` functions**, each with a contract in its doc comment and a test per clause: `substring` (traps, never clamps), `replace` (leftmost, non-overlapping, non-empty; empty needle returns the input), `repeat`, `pad_left`/`pad_right`, `trim`/`trim_left`/`trim_right`, the public `is_space` predicate (ASCII 0x09–0x0D and 0x20), `split_str`, `strip_prefix`/`strip_suffix`, `last_index_of`. `to_upper`/`to_lower` now document what they always did: ASCII only, scalars >= 0x80 pass through, and `to_upper` is not invertible.
- **`spec/language.md` §9 makes the embedded stdlib's public surface normative**, documented in `stdlib/README.md` and each function's doc comment — a forward-compatibility commitment. It restates the two load-bearing contracts inline: `regex` guarantees linear-time matching *and* a bounded compile, and `sort_by`/`sort_by_key` are stable.
- **Haskell is 93x faster on the regex suite** (26.04s → 0.28s user). Two changes: `NFData` is hand-emitted rather than `Generic`-derived (allocation 103.6 GB → 1.55 GB), and values are now forced at construction instead of at call boundaries, which removes the deep traversal entirely. That also fixes an asymptotic bug — the Pike VM's advertised Theta(n·k) was running Theta(n·k^2) because every `add_state` call re-forced the immutable NFA.
- **New op-count complexity harness.** Operation counts, not wall clock (rejected here as flaky on shared runners): run a workload at n and 2n and assert the ratio. `sort_by`, `join` and `big_to_text` each carry a doubling test that fails against their pre-fix implementations.
- `backend_c` orders struct typedefs before function-pointer typedefs; previously any generic instantiated over a tuple or record emitted C that would not compile, and both `check` and codegen passed.
- Zig's global cache is now shared across lockstep tests instead of rebuilt per test (1591 MB of per-test caches → one 43 MB cache).
- `spec/backend-guide.md` §4.20: an environment variable may toggle instrumentation but must never change what a program computes, which traps fire, or in what order.
- Known: three `strictness_sites` cells (Binary, Builtin, List) pass but do **not** fail when their emitter site is deliberately broken — GHC happens to order those operands correctly today. The ordering mechanism covers them by design, not by test.

## v0.5.0

- **Haskell `List<T>` is now `Data.Sequence`.** The backend previously represented lists as plain `[a]`, so every indexed op was O(n) and sequential append was quadratic. Now O(1) append and O(log n) index/update. Measured: 20k appends 2.70s → 0.61s; 40k appends 10.61s → 0.71s (was quadratic — quadruples when N doubles — now flat); 1M appends previously StackOverflowed, now completes in 2.35s (python: 1.00s for contrast); 100k indexed ops 2.39s → 0.69s. Generated Haskell changes shape but not observable behavior: assert-failure diagnostics byte-identical to python; all 41 lockstep targets across 7 backends plus the trap-strictness regression pass.
- `sudoc check` accumulates signature-pass errors instead of reporting only the first (records/enums/signatures/consts, passes 1–4). Hard barrier between passes so no pass runs on a poisoned context; a file with N independent signature errors reports all N. Single-error behavior and existing error text unchanged.
- New `bench/` directory: manual performance harness (`list_append.sudo`, `list_indexed.sudo`, `run.sh`) used for the F11 numbers above. Deliberately not wired into CI/bazel (action caching would confound timing).
- CI: GitHub Actions bumped off the deprecated Node 20 runtime (checkout v4→v7, upload-artifact v4→v7, download-artifact v4→v8, cache v4→v6, action-gh-release v2→v3, setup-bazel 0.15.0→0.19.0).
- Notes/docs: F2/F11 attribution and scope corrections (internal only).

## v0.4.0

- **BREAKING — `record`/`enum` names may no longer contain `_`.** Type names are the only bare user data inside generated type symbols, where `_` is the component separator; an underscore made distinct types collide onto one symbol (`record List_3i64` vs `List<int>`; `Map<a_b,c>` vs `Map<a,b_c>`), which backends emitted twice as invalid code. `sudoc check` now rejects such names at the declaration site with a CamelCase rename suggestion. No deprecation cycle. Migration: rename the type (the diagnostic tells you to what). Zero impact on the stdlib, examples, conformance corpus, or any known consumer — no underscore-bearing type name existed in any of them.
- Check-time guard: mangled-symbol uniqueness is enforced post-monomorphization (`types/mangle_check`) so colliding type symbols fail `sudoc check` loudly, naming both types. Retained permanently as an oracle against future mangle-grammar changes (unit tests build colliding `Ty` values directly now that no valid source can reach them).
- Backend hygiene: dead `ListSort` arm in `backend_rs` is now `unreachable!()` naming the invariant; `backend_zig` renames `unsupported()` → `unreachable_shape()` with internal-error framing (every call site is checker-guarded; "not yet implemented" misread as open gaps).
- Docs/notes: close stale footgun claims from a repo-wide sweep (retired global-arena model, decision-log backlog items that shipped, dangling cross-references). No runtime/API impact.
